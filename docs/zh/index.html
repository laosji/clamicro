它不是什么都拦

在你以为它会拦下每条命令之前,先看清默认值。

操作等多久到点
普通 10s 自动通过
高风险 —— rm -rf、force push、动 ~/.ssh 3 min 自动拒绝

也就是说:日常操作它是告诉你,高危操作它才是拦住你。两个数都能改 ——把第一个设成 0,就是每条都等你。无论哪种,Mac 都会提醒你。

什么都不出你的 Wi-Fi

为什么没有推送

两条远程通道都做出来过,又都删了。

第一条是带操作按钮的 ntfy 中转 —— 锁屏上直接批。它能用。它同时把控制面 交给了第三方。

第二条是 Bark:只发一句「有一条待审批」,控制面留在局域网。这已经是能做到的最克制的 版本了,而它换来的仍然只是「人不在时有东西能叫你」—— 代价是持续告诉一台外部服务器 「这里有个操作在等着」。

能上锁屏的通知必须过 APNs,那就必然是别人的服务器。所以答案是 macOS 本地通知, 完全不联网,再没有别的。

代价要说清楚:一旦你离开这台 Mac,没有任何东西会叫你。高危操作会等到超时 然后被拒绝。这是有意的默认 —— 人不该在咖啡馆里批准 rm -rf。

命令原文、审批决定、时间线和用量,全部走局域网直达你的 Mac。配对只有在你于 Mac 自己的屏幕上按下「允许」之后才会签发凭证。细节和威胁模型: 中文 README · SECURITY.md

一条命令。动任何东西之前它都会先问。

$npx clamicro install

macOS + iPhone,同一个 Wi-Fi · Node 18+

它会把要往 ~/.claude/settings.json 里写的内容原样列给你看, 等你确认,并且先备份。然后带你走一遍内置演示 —— 一条假的审批,让你在任何真东西 有风险之前,先真划一次。卸载只删它自己放进去的,可字节级验证。

能用吗?

Clamicro 没有遥测,也永远不会往外报 —— 这意味着除了我自己这台机器,我不知道它 在谁那儿能用。你要是装了,不管成没成我都真的想知道,尤其是没成的时候。
